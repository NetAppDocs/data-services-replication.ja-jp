= NetApp ReplicationのFAQ
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ./media/


[role="lead"]
このFAQでは、NetApp Replicationに関するよくある質問にお答えします。ONTAPシステム、Cloud Volumes ONTAP、およびAmazon FSx for ONTAPの間のレプリケーション関係の設定、管理、トラブルシューティングに役立つ概念、用語、および動作に焦点を当てています。



[[general-concepts]]
== 一般概念

.レプリケーションは、どのソースシステムとターゲットシステムの組み合わせをサポートしていますか？
レプリケーションは、Amazon FSx for ONTAP、Cloud Volumes ONTAP、およびオンプレミス ONTAP をサポートしています。これら3つのシステム間で任意の組み合わせでレプリケーションを設定できます。

.レプリケーションはどのようなデータ保護構成をサポートしていますか？
レプリケーションは、次の3つの構成をサポートしています：

* *シンプル*：複製はボリューム A からボリューム B へ行われます。
* *ファンアウト*：ボリューム A から複数のデスティネーションにレプリケーションが行われます。
* *カスケード*：レプリケーションはボリューム A からボリューム B へ、そしてボリューム B からボリューム C へと行われます。


.最初のレプリケーション転送時と、その後の転送時では、何が起こるのでしょうか？
ベースライン転送には、ソースデータの完全なコピーが含まれます。以降の転送には、ソースデータの差分（増分）コピーのみが含まれます。

.レプリケーションの利用には費用がかかりますか？
NetApp はレプリケーション自体の使用料を請求しませんが、適用されるデータの送受信料金についてはクラウド プロバイダにご確認ください。NetApp Console では、ストレージ システムやデータ サービスに接続するために Console エージェントをデプロイすると料金が発生します。Console からアクセスできるその他の一部の NetApp データ サービスは、ライセンス制またはサブスクリプション制です。

.レプリケーションを使用するには、ライセンスまたはサブスクリプションが必要ですか？
ConsoleやReplicationの使用を開始するために、ライセンスやサブスクリプションは必要ありません。オンプレミスのONTAP構成では、アクティブなSnapMirrorライセンスがインストールされている必要があります。



[[replication-policies]]
== レプリケーションポリシー

.ミラー ポリシーとバックアップ ポリシーの違いは何ですか？
レプリケーション ポリシーには 3 つの種類があります。

* *ミラー*：新しく作成されたSnapshotコピーをデスティネーション ボリュームにレプリケートします。ディザスタリカバリの準備や1回限りのデータレプリケーションに役立ちます。デスティネーション ボリュームはいつでもデータアクセス用にアクティブ化できます。
* *バックアップ*：特定のラベル付きSnapshotコピーをデスティネーション ボリュームにレプリケートし、通常はソース ボリュームよりも長く保持します。破損または失われたデータのリストアやコンプライアンス/ガバナンスの目的に役立ちます。
* *ミラーリングとバックアップ*：災害復旧と長期保存の両方を組み合わせたもので、各システムに標準で含まれているポリシーです。


デフォルトのポリシーがニーズに合わない場合は、System Manager を使用してカスタム ポリシーを作成できます。

.バックアップ ポリシーがスナップショット コピーをレプリケートしないのはなぜですか？
バックアップ ポリシーは、ソースボリュームのスナップショットポリシーで定義されたラベルと一致するラベルを持つスナップショットコピーのみを複製します。カスタムバックアップ ポリシーのラベルがスナップショットポリシーのいずれのラベルにも一致しない場合、システムはスナップショットコピーを複製できません。例えば、「daily」と「weekly」というラベルが付いたバックアップ ポリシーは、それらのラベルが付いたスナップショットコピーのみを複製します。

.デフォルトのポリシーを使用した場合、デフォルトのスナップショット保持設定はどうなりますか？
デフォルトのスナップショットポリシーでは、1時間ごと、1日ごと、1週間ごとのスナップショットコピーが作成され、それぞれ6つの1時間ごとのコピー、2つの1日ごとのコピー、2つの1週間ごとのコピーが保持されます。デフォルトのバックアップ ポリシーでは、日次および週次のスナップショットコピーが複製され、7つの日次スナップショットコピーと52の週次スナップショットコピーが保持されます。



[[setting-up-replication]]
== レプリケーションの設定

.データレプリケーションを設定する前に、何をチェックする必要がありますか？
データの複製を行う前に、以下の点を確認してください。

* ソースシステムとターゲットシステムはすでに存在している（または新たに作成する）。
* ソースボリュームとデスティネーション ボリュームで互換性のある ONTAP バージョンが実行されていることを確認してください。詳細については、link:https://docs.netapp.com/us-en/ontap/data-protection/compatible-ontap-versions-snapmirror-concept.html["互換性のある ONTAP バージョン"^] を参照してください。
* link:task-replicating-data.html["データ複製要件"]のシステム固有の要件を満たしていることを確認してください。


.クラスタ間 LIF 間でクラスタ ピアリングが正しく機能するために必要な条件は何ですか？
クラスタ間ネットワークは、クラスタ ピアがペアワイズフルメッシュ接続を持つように構成する必要があります。つまり、クラスタ ピア関係にある各クラスタのペアが、すべてのクラスタ間LIF間で接続性を持つということです。これは、複数のLIFを持つ ONTAP クラスタが送信元またはデスティネーションである場合に適用されます。

.カスタムのレプリケーションスケジュールを作成できますか？
レプリケーションを設定する際には、いくつかのデフォルトのスケジュールが利用可能です。別のスケジュールが必要な場合は、System Manager を使用してデスティネーション クラスタで新しいスケジュールを作成する必要があります。



[[managing-replication-relationships]]
== レプリケーション関係の管理

.レプリケーション関係がアイドル ステータスおよび未初期化ミラー状態を示している場合、それはどういう意味ですか？
これは、デスティネーション システムに障害が発生した後、再びオンラインに戻った場合に発生する可能性があります。定義されたスケジュールに従ってデータ レプリケーションを再開するには、デスティネーション システムから System Manager または CLI を使用してリレーションシップを初期化する必要があります。

.ブレーク、リシンク、リバースリシンクの各アクションの違いは何ですか？
これらの操作はそれぞれ異なる効果をもたらします。

* *Break*： ソース ボリュームとデスティネーション ボリューム間の関係を解除し、デスティネーション ボリュームをデータ アクセス用にアクティブ化します。通常、ソース ボリュームが破損、削除、またはオフライン状態のためにデータを提供できない場合に使用されます。
* *再同期*：切断された関係を再確立し、スケジュールどおりにレプリケーションを再開します。デスティネーション ボリュームの内容は、ソース ボリュームの内容で上書きされます。
* *リバースリシンク*：ソースボリュームとデスティネーション ボリュームの役割を反転させ、元のソースボリュームの内容をデスティネーション ボリュームの内容で上書きします。前回のレプリケーションからオフラインになるまでの間に元のソースボリュームに書き込まれたデータは保持されません。


.レプリケーション関係を削除するとどうなりますか？
ソースボリュームとデスティネーション ボリューム間のデータ保護関係を削除すると、ボリューム間のデータ レプリケーションが終了し、デスティネーション サイトから SnapMirror 関係が削除され、ソース サイトからその関係が解放されます。また、SnapMirror 関係を解除することで、デスティネーション ボリュームを一時的に読み取り / 書き込み操作のプライマリ サイトとして設定し、レプリケーション削除後もデスティネーションを独立して使用できるようにします。

.最大転送速度を無制限のままにせず、制限する必要があるのはなぜですか？
無制限の転送速度は、他のアプリケーションのパフォーマンスやインターネット接続のパフォーマンスに悪影響を与える可能性があります。レプリケーションの設定時に最大転送速度（メガバイト/秒単位で指定）を制限することをお勧めします。後でレプリケーション ステータス ページから編集することもできます。
